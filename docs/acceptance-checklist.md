# Peak Trekker 验收 Checklist v0.3

## 0. 使用规则

### 0.1 验收结论分级

每一项验收只允许填这 3 种结果：

* **通过**
* **不通过**
* **不适用**

禁止写：

* 差不多
* 基本可以
* 问题不大
* 先这样
* 后面再看

### 0.2 证据要求

任何宣称“通过”的验收项，至少要有以下证据之一：

* 真实浏览器截图
* 实际录屏
* 关键 DOM / selector 验证
* 明确的尺寸 / 坐标 / 数值证据
* 原始命令与原始结果输出

仅有“测试通过”不足以作为最终验收结论。  
视觉类、布局类、交互类问题，必须优先给真实浏览器证据。

### 0.3 视觉问题的额外要求

对于以下类型问题，必须提供更强证据：

* 按钮高度
* 卡片间距
* 图标尺寸
* 模块是否隐藏
* CTA 是否可见
* 移动端是否换行
* 页面是否横向溢出
* 分享模板是否遮挡
* 顶部操作区是否拥挤

要求：

* 至少提供 375px 宽度截图
* 必要时附 px 数值或浏览器 computed style
* 必要时附元素坐标或 bounding box

### 0.4 环境阻塞的处理规则

如果某项功能因环境问题无法完成验收：

* 该项仍判定为 **不通过**
* 必须额外标注：`[环境阻塞]`
* 必须说明阻塞类型，例如：
  * schema 未迁移
  * env 未配置
  * service role 缺失
  * bucket / 存储未配置
  * 第三方接口未接通
* 必须区分：
  * 是代码问题
  * 还是环境问题

### 0.5 验收顺序

建议固定按这个顺序验收：

1. 主线对齐
2. 全局 UI / 组件
3. 首页 / 意图分流
4. Explore（含三条路径入口）
5. Mountain Detail
6. Record / Trek / 留证
7. Activity / 我的记录
8. Share Engine / 水印相机
9. Community
10. Profile / Province Heat
11. FAQ / 山峰物料 / 地图天气
12. 轨迹导入
13. 截图识别
14. 来源标签
15. 商业化基础框架
16. 上线前主线可信度 / 技术收口
17. 回归与联动

### 0.6 基本设备标准

人工验收默认至少覆盖：

* 移动端基准宽度：**375px**
* 常规桌面宽度：至少 1 档
* 深色主题下的可读性
* 有图 / 无图 / 单图 / 多图 / 空数据 / 长文案场景

# 1. 主线对齐验收

## 1.1 产品主语

* [ ] 产品当前的核心对象仍然是“**我的一次真实山行**”
* [ ] Activity / Record 的战略地位高于 Community
* [ ] Community 被表达为公开层，而不是产品中心
* [ ] 山仍然是锚点，但不是唯一主角
* [ ] 分享被表达为活动结果的表达层，而不是复杂编辑器产品

## 1.2 首页与入口逻辑

* [ ] 首页不再只能服务“找山”这一个意图
* [ ] 首页或一级入口层面，至少能看出以下两个主方向：
  * 去找下一座山
  * 把这次结果带回来
* [ ] Explore 仍然是找山的主入口
* [ ] Community 未抢占首页主叙事
* [ ] `/prep` 或备赛相关入口未抢占主流程

## 1.3 对象边界

* [ ] 活动记录可以不发山友圈
* [ ] 山友圈内容必须基于活动记录生成
* [ ] 删除山友圈内容不影响活动记录本身保留
* [ ] Activity Detail 与 Community Detail 在结构和职责上清晰分离

## 1.4 海拔优先级

* [ ] 海拔在 Explore 中清晰可见
* [ ] 海拔在 Mountain Detail 首屏清晰可见
* [ ] 海拔在 Trek / Record 中被高优先展示
* [ ] 海拔在 Share 素材中属于默认高优先字段
* [ ] 海拔在我的记录 / 活动回看中具备高识别度

# 2. 全局 UI / 组件验收

## 2.1 通用操作 icon 化

* [ ] 返回操作使用 icon，不再使用纯文字“返回”
* [ ] 关闭操作使用 icon，不再使用纯文字“关闭”
* [ ] 分享操作使用 icon，不再使用纯文字“分享”
* [ ] 编辑操作使用 icon，不再使用纯文字“编辑”
* [ ] 更多操作使用 icon，不再使用纯文字“更多”
* [ ] 删除 / 举报 / 下载等高频工具动作优先 icon 化
* [ ] icon 按钮点击热区一致
* [ ] Icon Button 尺寸统一为 44x44px
* [ ] icon 大小统一为 20px
* [ ] icon 按钮在 375px 下不拥挤、不换行

## 2.2 字体与层级

* [ ] 页面主标题统一使用 `headline-m`
* [ ] 帖子标题、活动标题、山峰名统一使用 `title-l`
* [ ] 区块标题统一使用 `title-m`
* [ ] 正文统一使用 `body-l` 或 `body-m`
* [ ] 按钮文字统一使用 `label-m`
* [ ] 辅助说明、时间戳、单位统一使用 `label-s`
* [ ] 没有使用刻度外字号

## 2.3 间距与布局

* [ ] 页面左右边距统一为 `space-4`
* [ ] 卡片内边距统一为 `space-4`
* [ ] 卡片间距统一为 `space-3`
* [ ] 模块间距统一为 `space-6`
* [ ] 大模块间距统一为 `space-8`
* [ ] 没有使用刻度外间距值

## 2.4 按钮系统

* [ ] 所有 Primary / Secondary / Tertiary 按钮高度为 44px
* [ ] 所有按钮圆角为 `radius-md`
* [ ] 所有按钮 padding-x 为 `space-5`
* [ ] 所有按钮字号为 `label-m`
* [ ] 同一组并排按钮规格像素级一致
* [ ] 每个视觉层级最多 1 个 Primary
* [ ] 没有绕过 token 的自定义按钮样式

## 2.5 卡片系统

* [ ] 卡片内边距为 `space-4`
* [ ] 卡片圆角为 `radius-lg`
* [ ] 卡片内部区块间距为 `space-3`
* [ ] 不存在“卡片套卡片”式嵌套结构
* [ ] Hero / 大图容器不出现过重叠层

## 2.6 色彩 Token

* [ ] 所有新改动页面只使用 `color-*` 语义 token
* [ ] 新改动中没有新增硬编码 hex
* [ ] 语义使用正确：成功 / 警告 / 错误不混用
* [ ] 主 CTA 使用主色，不滥用强调色
* [ ] 主线页面未继续扩大 color debt

## 2.7 文案与语气

* [ ] 正式 UI 中无 debug / qa / mock / helper / fallback 等开发味词汇
* [ ] 错误提示是用户视角，而不是系统视角
* [ ] 锁定 / 限制提示是引导式，而不是冷冰冰拦截
* [ ] 审核中 / 未通过提示不会让用户感觉“这趟白走了”
* [ ] 没有测试味、产品功能味、内部术语直接暴露给用户

## 2.8 移动端适配

* [ ] 375px 下页面无横向滚动
* [ ] 顶部工具栏不换行
* [ ] 卡片操作区不换行
* [ ] 弹窗底部按钮区不换行
* [ ] 固定底部 CTA 不遮挡主内容
* [ ] 长文案不会顶破布局
* [ ] 多图 / 无图 / 单图情况下布局仍正常

# 4. Explore 页验收

## 4.1 页面结构

* [ ] 首屏是搜索 + 上二下一入口区 + 过渡文字 + 筛选 chips + 山峰列表
* [ ] 上方两张并排入口卡片同等视觉权重：左「导入记录」、右「识别截图」
* [ ] 「导入记录」文案为“导入轨迹文件，分享你的登顶记录”
* [ ] 「识别截图」文案为“上传其他 APP 轨迹截图，分享你的登顶记录”
* [ ] 过渡文字为 `找山出发 · 挑一座适合你的山进行登顶打卡`
* [ ] 三条路径入口（选山记录 / 轨迹导入 / 截图识别）具有同等视觉权重
* [ ] 轨迹导入和截图识别入口不降格为"补签"或"二级功能"样式
* [ ] 入口文案符合“标题 + 行为描述 + 行为结果”
* [ ] 不出现社区内容流式干扰
* [ ] 不出现收藏 / 想去入口
* [ ] 页面首屏可以直接开始浏览山峰或选择导入/识别路径

## 4.2 山峰卡片信息

* [ ] 每张卡片都有主图
* [ ] 每张卡片都有山峰名
* [ ] 每张卡片都有地点
* [ ] 每张卡片都有海拔
* [ ] 每张卡片都有距离或预计时长

## 4.3 卡片视觉

* [ ] 主图比例统一
* [ ] 图片不会拉伸变形
* [ ] 无图时有合理兜底，不出现丑陋空白块
* [ ] 山峰名、海拔、难度、执照信息易于扫读
* [ ] 海拔不是被弱化的辅助字段

## 4.4 交互

* [ ] 点击山峰卡片进入详情页
* [ ] 搜索可正常工作
* [ ] 筛选可正常工作
* [ ] 搜索与筛选组合后结果正确
* [ ] 游客可浏览 Explore 与 Detail，不强制先登录
