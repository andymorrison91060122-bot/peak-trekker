# Peak Trekker 产品主线对齐稿 v0.3

## 1. 文档目标

本文件用于明确 Peak Trekker 当前阶段的产品主语、对象层级、入口逻辑、功能边界和阶段路线，并作为后续产品决策、设计调整、Codex 执行和人工验收的最高优先级方向文档。

本文件解决的问题不是"某个页面怎么改"，而是：

* 我们到底是谁
* 当前阶段最该强化什么
* 哪些方向明确不做
* 现有文档冲突时以什么为准
* 上线前有哪些事项不能遗漏

## 3. 一句话定义

**Peak Trekker 是一个以山为锚点、以单次真实山行为核心对象、以海拔与登顶证据为信任符号、以分享和回看为长期价值的产品。**

它不是重导航工具，不是泛社交社区，也不是单纯的海报生成器。
它要做的是：

* 帮用户更快找到值得去的山
* 帮用户把一次真实山行可信地留下来
* 帮用户把这次山行整理成好看、可回看、可分享的个人资产
* **帮用户把已有的山行记录（无论来自哪个平台）快速转化为高质量的分享内容**

---

## 4. 产品主语

**Peak Trekker 的主语不是"山"，也不是"帖子"，而是"我的一次真实山行"。**

这意味着：

* 山负责提供锚点、决策上下文和安全边界
* Activity / Record 是核心对象，不再只是社区附属物
* Share 是表达层，不是编辑器产品
* Community 是公开层，不是产品中心
* Profile / Province Heat 是长期归属层，不是单纯的数据面板

## 5. 六条差异化方向

### 5.1 找山更顺

产品仍然要保留"找山"价值，但重点不是堆更多泛标签，而是更快帮助用户找到一座**适合自己、值得去**的山。

### 5.2 接入更宽

产品不能只服务"从山脚就打开 Peak Trekker 的用户"，还要接住这些真实场景：

* 到山顶才想起来打开
* 用别的设备记录完，再回来整理
* 先有结果，再补记录
* 先有照片，再做留证

**v0.2 升级**：接入更宽不再只是"后续可扩展"的方向，而是当前阶段的核心入口策略。产品必须在 Explore 层面提供三条同等重要的路径：

1. **选山记录**：选山 → 出发 → GPS 实录 → 活动沉淀 → 分享
2. **轨迹导入**：上传 GPX/FIT 文件 → 系统解析 → 自动/手动匹配山峰 → 活动沉淀 → 分享
3. **截图识别**：上传其他 App 的记录截图 → OCR 提取字段 + 轨迹颜色分割重绘 → 用户确认 → 活动沉淀 → 分享

三条路径产出的内容在产品内具有同等地位，但通过来源标签区分可信度层级。

### 5.3 记录更真

产品必须继续坚持真实优先。
公开内容、热力贡献、可传播活动，都应尽量建立在有效记录或有效证据之上。

**v0.2 补充**：真实性不等于只接受 GPS 实录。三条路径各有其可信度层级，通过来源标签让用户和社区自行判断，而不是用技术手段把非实录用户挡在门外。

### 5.4 海拔被看见

海拔不是普通字段，而是 Peak Trekker 的 **signature cue**。
它既是目标感，也是过程感，也是结果证明。

### 5.5 分享更美

分享是核心价值之一，但方向是**少而精、快而好看**。
用户需要的是选择展示什么，不是深度排版设计。

**v0.2 补充**：分享更美也包括帮用户把来自其他平台的记录截图转化为 Peak Trekker 风格的高质量分享素材。截图中的轨迹应被重新提取和美化渲染，而不是直接贴原截图。这是产品的核心竞争力之一。

### 5.6 回看更有意义

"我的记录"不应该只是冰冷的数据列表，而要逐步演进成一个**私人山行档案馆**。

## 6. 三条入口路径（v0.2 新增）

### 6.1 路径一：选山记录

这是传统的主路径。用户在 Explore 中找山，进入 Mountain Detail 做决策，然后开始 GPS 实录。

**前置要求**：必须先确定目标山峰。

**可信度**：最高。有完整 GPS 过程数据。

**来源标签**：`GPS VERIFIED`

### 6.2 路径二：轨迹导入

用户在高驰、佳明、Suunto 等设备或 App 上完成记录后，将 GPX/FIT 文件导入 Peak Trekker。

**前置要求**：无需先选山。系统根据轨迹坐标自动匹配山峰，用户可确认或手动修改。未匹配到山峰时，仍允许生成活动和分享内容。

**可信度**：中。有完整轨迹数据但来源为外部。

**来源标签**：`UPLOADED`

### 6.3 路径三：截图识别

用户在两步路、六只脚、行者等 App 完成记录后，不做任何导出操作，只需截图记录页面，上传到 Peak Trekker。

**技术流程**：

1. 用户上传截图
2. OCR 提取文字信息：距离、时长、海拔、日期、地点等
3. 轨迹提取：系统自动识别截图中的轨迹线颜色 → 颜色阈值分割 → 骨架化 → 坐标点序列 → 贝塞尔曲线平滑
4. 以品牌绿 `#7ef0b4` 重新渲染轨迹
5. 系统整理识别结果，展示给用户确认，所有字段均可编辑
6. 合理性校验通过后生成活动对象，可直接进入分享

**前置要求**：无需先选山。系统根据 OCR 提取的地点信息尝试匹配，用户可确认或跳过。

**可信度**：较低。本质是用户自报 + OCR 辅助。

**来源标签**：`UPLOADED`

**轨迹精度要求**：不高。轨迹重绘的目的是生成好看的分享素材，不是还原精确地理路线。允许平滑修正，允许与原始轨迹有偏差。它不是导航，不需要精确。

**合理性校验**：只设上限，不设下限。

* 平地速度上限：12–15 km/h（覆盖越野跑精英水平）
* 有海拔场景：每 100m 正爬升折算 1km 等效距离
* 用总等效距离 ÷ 时长判断是否超限
* 超限时提示用户复核，不强制拦截
* 不校验下限（用户走走停停、扎营过夜均为正常）

### 6.4 三条路径的统一原则

* 三条路径在 Explore 入口层面具有同等视觉权重
* 三条路径最终都产出活动对象，活动对象结构一致
* 活动对象通过来源标签区分可信度，标签在分享海报和山友圈卡片中可见
* 三条路径都可以进入分享素材生成链路
* 截图识别和轨迹导入路径允许不绑定山峰

## 7. 商业化方向（v0.2 新增）

### 7.1 核心模型

**基础模板永久免费，高级模板限时免费 → 付费。**

用户可以无限制地记录、导入、识别和管理自己的山行活动。
付费节点只发生在高级分享模板的无水印导出环节。

### 7.2 模板层级

初始模板池为基础 2 个 + 高级 8 个，共 10 个模板。

基础层永久免费：

| ID | 名称 | 上半区 | 下半区 |
| --- | --- | --- | --- |
| `basic-classic` | 经典 | 轨迹线（MVP 无地图底图层） | 山峰名、海拔大字 + 距离 / 时长 / 爬升 / 日期横排 |
| `basic-data` | 数据 | 海拔数字居中超大 + 山形纹理 | 次级数据横排 |

`basic-minimal` 在 v0.3 删除：MVP 无地图底图时，它与 `basic-classic` 的视觉重复。

高级层在 MVP 阶段限免，正式商业化后进入付费层：

| ID | 名称 | 核心特征 |
| --- | --- | --- |
| `premium-photo-composite` | 照片合成 | 照片全屏 + 轨迹叠层 + 底部数据 |
| `premium-photo-overlay` | 照片叠层 | 照片全屏 + 左侧数据纵排 + 左渐变过渡 |
| `premium-bold-number` | 大字覆盖 | 照片 + 超大半透明海拔数字 |
| `premium-data-scatter` | 数据散布 HUD | 照片 + 数据散布四角 |
| `premium-mono-film` | 黑白影调 | 照片自动转黑白 + 底部数据条 |
| `premium-altitude-profile` | 海拔剖面 | 海拔折线图 + 数据，登山独有 |
| `premium-summit-certificate` | 山峰证书 | 平面设计勋章 + 等高线纹理 |
| `premium-vertical-story` | 竖排长卡 | 照片 + 轨迹 + 数据纵排（路线层 FU-5 后补） |

`premium-split-view` 在 v0.3 删除：用户上传图片后，它与 `premium-photo-composite` 的主视觉重复。

每个基础和高级模板都支持三种背景模式：照片合成、默认背景、透明水印导出。所有 10 个模板（含 `premium-summit-certificate`）都支持照片合成，MVP 阶段不允许“某些模板不支持图片”的特例。

### 7.3 付费方式

* 月度会员：所有高级模板无限使用
* 单次解锁：本次导出使用高级模板
* 具体定价在商业化激活时确定

### 7.4 预览与付费 Gate

* 用户可免费生成并预览分享素材
* 基础模板始终可无水印导出
* MVP 阶段（v0.8）所有模板免费，高级模板显示「限免」标签，体验与免费模板一致
* 正式版（v1.0）通过 feature flag 启用高级模板付费
* feature flag 打开后，导出高级模板时通过 `checkTemplateAccess()` 判断权限
* 未解锁高级模板时，预览态显示锁 icon、40% 遮罩和斜置「Peak Trekker 预览版」付费水印
* 付费后或限免期间不显示付费水印
* 发布到山友圈不触发模板付费 Gate

### 7.5 实现策略

* MVP 阶段（v0.8）：全部免费，不启用付费
* 正式版（v1.0）：通过 feature flag 启用高级模板付费模式
* feature flag 默认关闭，代码和 schema 在 v0.8 即部署到位
* 需要在 `profiles` 表预留 `subscription_tier` 和 `premium_template_unlocked_until` 字段
* 分享生成链路中预埋 `checkTemplateAccess()` gate 函数，flag 关闭时高级模板免费
* MVP 阶段在已有 SVG 模板系统上做调试 + 减法；Satori（HTML-to-image）重写作为 V1.1+ 长期演进方向，本期不做

品牌标识与付费水印必须区分：

* Peak Trekker logo + 文字永久存在于所有模板底部，是品牌传播，不是付费限制，用户不可移除
* 「Peak Trekker 预览版」斜置文字只在 feature flag 打开、用户未付费、预览高级模板时出现

### 7.6 明确不做

* 不对记录/导入/识别功能收费
* 不对山友圈浏览和互动收费
* 不做广告变现
* 不做复杂的多级会员体系

## 8. 来源标签与可信度分层（v0.2 新增）

### 8.1 标签定义

| 来源标签 | 对应路径 | 可信度 | 说明 |
|---|---|---|---|
| GPS VERIFIED | 选山记录 | 最高 | 品牌 logo + 分隔线 + ✓ + 英文，深绿底 + 薄荷绿边框；有完整 GPS 过程数据，经过 summit 核验 |
| UPLOADED | 轨迹导入 / 截图识别 | 中/较低 | 文档 icon + 英文，深灰底 + 灰色边框；数据来自外部，系统未参与过程采集 |

### 8.2 标签使用场景

尺寸规则：

* 大：约 28px，用于分享海报底部
* 中：约 24px，用于活动详情页
* 小：约 20px，用于山友圈和我的记录列表

展示位置：

* 分享海报：来源标签在海报底部展示
* 山友圈卡片：来源标签在活动数据区右侧展示
* 活动详情页：来源标签在海拔旁展示
* 我的记录：来源标签在活动卡片右下展示

### 8.3 标签对权益的影响（后续阶段）

当前阶段所有来源的活动均可发布山友圈、生成分享素材。
后续阶段可根据社区反馈，对不同来源的活动在热力贡献、精选资格等维度做差异化处理。当前不做。

## 9. 首页与一级入口原则

### 9.1 战略判断

**Explore 很重要，但不再等于产品唯一首页逻辑。**

### 9.2 Explore 的升级职责

Explore 从"纯找山页"升级为"三条路径的统一入口"。页面结构采用上二下一：

* 上方两张并排入口卡片，视觉权重相同：
  * 左卡片「导入记录」：导入轨迹文件，分享你的登顶记录
  * 右卡片「识别截图」：上传其他 APP 轨迹截图，分享你的登顶记录
* 过渡文字：`找山出发 · 挑一座适合你的山进行登顶打卡`
* 下方展示筛选 chips + 山峰卡片列表，承接选山记录路径

入口文案统一采用“标题 + 行为描述 + 行为结果”的格式。三条入口不分主次，不把导入和截图识别降格为活动补签或二级功能。

### 9.3 首页职责

首页不应继续只回答"下一座山去哪"，而应开始承担**意图分流**职责。

当前阶段推荐的首页主分流方向：

* **去找下一座山**
* **把这次结果带回来**（包含轨迹导入和截图识别）

辅助入口可以包括：

* 回看我的山行
* 继续上次未完成整理
* 查看我的省域进度

### 9.4 实施原则

首页逻辑可以分阶段调整，不要求一次性重构所有底部导航；
但从产品策略上，必须明确：

> 产品入口不能只服务"找山"，还要服务"带回结果"和"回看资产"。

## 10. 记录对象的证据分层

为了兼容真实使用场景，同时守住真实性边界，记录建议按三层理解：

### 10.1 完整山行

有较完整过程证据的活动对象。
这是最完整、最可信、最适合公开传播的记录类型。
**来源**：GPS 实录。

### 10.2 登顶留证

过程不一定完整，但到达结果有明确证据。
适用于"到顶才打开""只有到顶素材""后补结果"的场景。
**来源**：GPS 实录（部分过程）。

### 10.3 外部导入

数据来自外部平台，通过轨迹文件或截图导入。
可以保留完整的数据内容，但过程证据由外部平台提供，Peak Trekker 未参与采集。
**来源**：轨迹导入 / 截图识别。

### 10.4 个人归档

更偏私人留存的记录。
可以保留记忆价值，但不一定自动获得全部公开资格。

### 10.5 原则

这个分层的目的不是抬高门槛，而是：

* 不把真实用户挡在门外
* 不把所有记录混成同一可信等级
* 为未来的导入轨迹、补签、审核和公开资格打基础
* 让用户和社区可以自行判断内容可信度

## 11. 海拔的产品地位

海拔必须被正式定义为 Peak Trekker 的高优先级信号。

### 11.1 出发前

海拔代表目标感：
**我要去多高的地方。**

### 11.2 过程中

海拔代表临场感：
**我现在到了多高。**

### 11.3 结束后

海拔代表结果证明：
**我这次抵达了哪里。**

### 11.4 落地原则

海拔不一定单独成为一个独立功能页，但必须在以下链路里被优先看见：

* Explore / Mountain Detail
* Trek / 记录过程
* Share / 分享素材
* Activity / 回看页
* 我的记录 / 档案馆

## 12. 分享系统边界

### 12.1 分享系统是什么

它是活动结果的快速表达系统。

### 12.2 分享系统不是什么

它不是专业运动图表工具，也不是复杂海报编辑器。

### 12.3 当前阶段允许的选择权

分享编辑器最多做到三层：

* 选模板（10 个模板单行横滑平铺，高级模板用「限免」/「付费」角标区分，不使用基础 / 高级 Tab）
* 选主图 / 背景
* 选展示哪些字段（内联字段选择器，不进入二级页面）

字段选择器规则：

* 必选字段：海拔、总距离，不可隐藏
* 可选字段：时长、爬升、日期、地点、配速、山峰名，默认开启，可关闭
* 三条路径产出的活动都支持字段选择器
* 每个字段行包含拖拽排序手柄、字段名、当前值、编辑入口、显示 / 隐藏开关
* 未识别时，海拔和总距离必须由用户手动填写
* 字段选择器内联展示在分享编辑器中，用户调整后预览区实时更新

分享模板生成规则：

* MVP 阶段在已有 SVG 模板系统上做调试 + 减法
* Satori（HTML-to-image）重写作为 V1.1+ 长期演进方向，本期不做
* `regression-debt.md` 中的 SVG 模板冻结项保留，等 V1.1+ Satori 迁移时一并解冻
* 所有模板都支持照片合成 / 默认背景 / 透明水印导出三种背景模式
* 透明水印导出是主要功能按钮，不是 toggle 开关，提供棋盘格预览、保存到相册和分享能力
* 透明水印导出生成的水印形态跟随当前选中模板，不固定为 `basic-classic` 样式，服务端 PNG 端到端真实轨迹验证列入 FU-9 验收

### 12.4 当前阶段明确不做

* 大量专业图表
* 复杂拖拽排版
* 过多模板商城化
* 训练分析型图层
* 地图开关、顶部右上「预览」按钮和「更多 ...」按钮
* Satori（HTML-to-image）模板重写（V1.1+ 长期方向）

### 12.5 付费与预览（v0.2 新增）

* 用户可免费生成和预览分享素材
* 2 个基础模板始终可无水印导出
* 8 个高级模板在 feature flag 关闭时免费，flag 打开后按模板权限判断
* 未解锁高级模板时可触发付费引导或水印预览
* 具体付费策略见第 7 章

## 13. 我的记录：从列表走向档案馆

### 13.1 方向定义

"我的记录"长期应演进为 **私人山行档案馆**。

### 13.2 它不应该是什么

* 不只是数据列表
* 不只是发布历史
* 不只是相册
* 不只是成就墙

### 13.3 它应该是什么

它应该帮助用户保留少而精的记忆锚点，例如：

* 这次最能代表它的一张图
* 一个最关键的时刻
* 一句最想记住的话
* 一组最值得回看的结果数据

### 13.4 表达原则

一层看记忆，二层看事实，三层才看传播。

## 19. 本文件生效后的判断标准

后续所有产品和执行判断，统一先问这 5 个问题：

1. 它是否服务于"我的一次真实山行"这个主语？
2. 它是在强化核心资产层，还是在制造新分支？
3. 它是在帮助用户更真实记录、更好回看、更顺畅分享，还是在把产品带去别的赛道？
4. 它是否会与现有文档或当前阶段边界冲突？
5. 它是否在让更多真实用户更低门槛地进入产品并产出内容？

只要这五个问题里出现明显冲突，就不进入执行。
