# Peak Trekker 发布优先级矩阵 v0.2

## 1. 文档目标

本文件用于统一 Peak Trekker 在当前阶段的发布优先级、上线前必须收口事项、上线后第一波差异化事项，以及明确后置范围。

它的作用不是替代 PRD，也不是替代验收清单，而是回答下面三个问题：

1. 上线前哪些事情必须做完
2. 哪些事情是下一阶段差异化，但不应该抢占当前发布节奏
3. 哪些事情明确不属于当前范围，避免 Codex 顺手扩展

---

## 2. 使用规则

### 2.1 优先级定义

#### P0｜上线前必须收口
只要该层存在关键项"不通过"，整体版本就不能判定为可发布。

#### P1｜上线后第一波差异化
不阻塞本次上线，但一旦主线稳定，应优先推进。

#### P2｜后续扩展
确认主线跑通、数据与用户反馈成立后，再进入评估与执行。

### 2.2 任务归属规则

任何新增任务，在进入开发前，必须先明确归属：P0 / P1 / P2 / 明确不做。
如果无法明确归属，默认不进入开发。

### 2.3 与其他文档的关系

* 产品方向冲突，以 `product-mainline-alignment.md` 为准
* 交互与视觉冲突，以 `ui-interaction-spec.md` 为准
* 验收与上线判定，以 `acceptance-checklist.md` 为准
* 已知技术债与环境债，以 `regression-debt.md` 为准
* 颜色硬编码收口，以 `color-debt.md` 为准

---

## 3. 当前阶段一句话判断

当前阶段不是继续扩功能版图，而是：

> **先把三条入口路径（选山记录 / 轨迹导入 / 截图识别）→ 活动沉淀 → 分享这条主线收稳，同时预埋商业化基础，再做首页分流、档案馆表达和付费激活。**

## 4.2 三条入口路径落地（v0.2 新增）

### 目标
让产品从"只服务选山记录用户"升级为"同时接住选山、导入、截图三类用户"。

### 必须完成

#### Explore 入口分流
* Explore 页面三条路径入口 UI 设计与实现
* 三条入口同等视觉权重
* 入口文案用户视角

#### 轨迹导入
* GPX/FIT 文件上传与解析
* 轨迹数据提取（距离、时长、海拔、爬升、轨迹点序列）
* 山峰自动匹配（基于轨迹坐标）
* 用户确认/修改/跳过匹配
* 活动对象生成
* 来源标签 `上传数据` 标记

#### 截图识别
* 截图上传 UI
* OCR 文字信息提取（距离、时长、海拔、日期、地点）
* 轨迹颜色分割：用户取色 → 颜色阈值分割 → 骨架化 → 坐标序列 → 贝塞尔曲线平滑
* 轨迹以 Peak Trekker 风格重新渲染
* 山峰匹配（基于地点信息）
* 用户确认/修改所有识别结果
* 合理性校验（只设上限）
* 活动对象生成
* 来源标签 `上传数据` 标记

#### 来源标签体系
* `GPS 验证` / `上传数据` 两种标签
* 在分享海报、山友圈卡片、活动详情页中展示

### 完成标准
* 三条路径均可从 Explore 入口进入
* 三条路径均可走完到活动对象生成
* 三条路径均可进入分享素材生成链路
* 来源标签在所有展示场景中正确显示
* 截图识别的合理性校验正常工作

## 4.3 主线可信度与技术 blocker 收口

### 目标
先把会伤害"真实记录 + 活动沉淀 + 分享传播"可信度的问题收稳。

### 必须处理
* `/trek` 的 `verify_summit_checkin` 稳定性
* 真实上传链路 / 存储桶环境验证
* poster / 分享主链路稳定性
* poster / 分享缩略图性能的主路径风险
* Admin Checkin Review 权限校验
* `checkins` 表 `UPDATE` RLS policy
* 当前执行中工作包的环境级 blocker 收口

### 完成标准
* 主线场景下 summit 核验不会频繁误判
* 上传、访问、发布复用链路跑通
* 分享图主路径稳定可用
* 后台关键管理路径权限正确
* 没有未标注的环境 blocker 遗留

## 4.4 商业化基础框架（v0.2 新增）

### 目标
在 MVP 阶段预埋完整的付费基础设施，通过 feature flag 控制，不影响免费体验。

### 必须完成
* `profiles` 表增加 `subscription_tier`（默认 `free`）和 `free_shares_remaining`（默认 3）字段
* 分享生成链路预埋 `checkShareQuota()` gate 函数（flag 关闭时返回 true）
* 海报预览水印组件开发（flag 关闭时不渲染）
* feature flag 机制搭建（环境变量控制）

### 完成标准
* schema 已部署，字段存在
* 代码中 gate 函数和水印组件已就位
* feature flag 关闭时用户体验与当前完全一致
* feature flag 打开时付费逻辑可正常工作

* 是否触碰地图 / 天气 / 分享 / 记录边界

* 首页逻辑

* 三条入口路径

* 分享模板体系
* 商业化模型

* 地图 / 天气职责

### 8.3 每个工作包完成后都必须回答

* 这次改动属于哪一层优先级？
* 是否有未经批准的功能扩展？
* 是否引入了新 blocker？
* 是否影响了主线文档和验收清单？
* 是否需要更新 debt 文档？

## 9. 版本放行判断

只有当以下条件全部成立时，版本才可进入放行讨论：

* P0 文档对齐完成
* P0 技术 blocker 收口完成
* **P0 三条入口路径完整落地**
* **P0 来源标签体系落地**
* **P0 商业化 schema + feature flag 预埋完成**
* P0 山峰内容与物料最小包到位
* P0 UI / 文案 / 主线 polish 到位
* FAQ 可用
* 轻量地图 / 天气方案确定且可用
* 主线验收走完
* 无隐藏环境 blocker

只要上述任何一项不成立，默认结论都不是"可发布"。
