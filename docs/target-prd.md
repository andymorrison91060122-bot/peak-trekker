# Peak Trekker To-Be PRD v0.3

## 1. 产品定位

Peak Trekker 是一个面向登山 / 徒步场景的移动优先产品：

* 先帮助用户**找到值得去的山**
* 再通过 **GPS 实录、轨迹导入、截图识别，及照片补签** 留下一次真实山行
* 最后把这次山行沉淀成 **个人活动、可传播素材、山友圈内容、所属省份的长期归属贡献**

一句话定义：

> **一个以山为锚点、以单次真实山行为核心对象、以海拔与登顶证据为信任符号、以分享和回看为长期价值的登山产品。**

### 1.1 我们是谁

Peak Trekker 不是重地图导航工具，不是泛社交社区，也不是单纯的海报生成器。
它要做的是：

* 帮用户更快找到一座适合自己、值得去的山
* 帮用户把一次真实山行可信地留下来
* 帮用户把这次山行整理成好看、可回看、可分享的个人资产
* 帮用户把已有的山行记录（无论来自哪个平台）快速转化为高质量的分享内容

### 1.2 我们不靠什么竞争

我们当前不依赖以下能力作为主定位：

* 专业级重地图导航
* 大规模 UGC 路线地图生态
* 组队 / 备赛工具链
* 泛内容社交广场
* 复杂训练分析和专业图表系统

### 1.3 我们的核心差异化方向

1. **找山更顺**
2. **接入更宽**
3. **记录更真**
4. **海拔被看见**
5. **分享更美**
6. **回看更有意义**

### 1.4 设计资源引用与权威源

文档引用设计资源时统一使用仓库内路径：

* 组件 JSX：`design-system/ui_kits/mobile/[文件名].jsx`
* 模板 PNG：`design-system/templates/[文件名].png`
* 组件规范：`design-system/components/[文件名].png`
* Token：`design-system/colors_and_type.css`
* 使用指南：`design-system/DESIGN_GUIDE.md`

当设计资源之间存在矛盾时，优先级为：

1. ChatGPT PNG（模板视觉 + 组件规范）
2. `design-system/colors_and_type.css`
3. `design-system/DESIGN_GUIDE.md`
4. Claude Design V4 JSX
5. Handoff 文档

JSX 中的像素值与 token 文件矛盾时，以 token 为准；JSX 中的文案与 PNG 规范矛盾时，以 PNG 为准。

## 2. 产品阶段目标

### 2.1 当前阶段核心目标

第一，建立稳定的 **找山 → 决策 → 记录 / 留证 → 活动沉淀** 主链路。
第二，让产品不仅能服务"从山脚开始记录"的用户，也能接住"结果现在才被带回来"的用户——通过三条同等重要的入口路径。
第三，把"单次真实山行"做成独立、完整、可信、易回看的核心对象。
第四，让海拔、登顶与关键证据在找山、记录、分享、回看四段里都被优先看见。
第五，强化分享素材系统，让用户每次有效山行都能快速产出可传播内容。
第六，山友圈继续只做真实活动驱动的信息流，不做泛社交广场。
第七，省域热力继续只做轻量归属机制，不做复杂竞技。
第八，上线前必须同步完成主线可信度、关键物料、文案体验、FAQ、轻量地图 / 天气方案的收口。
第九，建立商业化基础框架（schema + feature flag），为后续分享付费做好准备。

### 2.2 当前阶段明确不做

不做收藏 / 想去体系。
不做重地图导航能力。
不做专业向导式路线建议。
不做完整备赛工具链。
不做重成就墙。
不做复杂省域竞技系统。
不做与登山弱相关的泛内容社交。
不把分享系统做成专业图表工具或复杂模板编辑器。
不做广告变现。
不做复杂多级会员体系。

### 2.3 当前阶段必须补齐但不走重投入的能力

虽然当前阶段明确不做重地图导航和专业天气服务，但**上线前必须补齐轻量地图参考能力与轻量天气接口方案**，用于：

* Mountain Detail 决策辅助
* Trek 轻量辅助
* 分享素材辅助
* FAQ 和用户说明中的明确预期管理

## 3. 核心设计原则

### 3.1 主语优先

产品的核心对象是"**我的一次真实山行**"，不是山本身，也不是帖子本身。

### 3.2 决策优先

Explore 负责找山，Mountain Detail 负责出发决策。
首页不再只服务找山，但找山仍是最重要的主路径之一。

### 3.3 真实优先

所有公开内容、热力贡献、可传播活动，都应尽量建立在有效记录或有效证据之上，弱化"空发帖"。
不同来源的活动通过来源标签区分可信度，让用户和社区自行判断。

### 3.4 接入更宽

产品不能只服务"全程都在 Peak Trekker 里完成记录"的用户，也要接住以下真实场景：

* 到山顶才想起来打开
* 用别的设备记录完，再回来整理
* 先有照片，再做留证
* 先有结果，再补记录
* **在其他 App 完成记录后，截图上传即可生成分享内容**
* **从运动手表导出轨迹文件，导入即可生成活动**

三条入口路径（选山记录 / 轨迹导入 / 截图识别）在产品中具有同等地位。

### 3.5 海拔被看见

海拔不是普通字段，而是 Peak Trekker 的高优先级产品信号。
它既代表目标感，也代表过程感，更代表结果证明。

### 3.6 简洁传播

分享系统提供有限但关键的选择权，不演化成复杂编辑器。
重点是"快、好看、好传播"，而不是"功能越多越专业"。

### 3.7 移动优先

所有关键页面默认以手机端体验为基准设计，特别是操作区、弹窗、底部按钮区和固定 CTA。

### 3.8 通用操作 icon 化

关闭、分享、编辑、返回、更多、删除、下载、举报等高频动作，优先用 icon button，不再优先用纯文字操作。

## 4. 信息架构

## 4.1 一级模块

### 首页 / 意图分流

首页不应长期只等于 Explore，而应逐步承担**意图分流**职责，优先帮助用户判断这次进入产品是为了：

* 去找下一座山
* 把这次结果带回来
* 回看自己已有的山行资产

首页意图分流是已确定的战略方向；本次上线前只要求文档与信息架构对齐，正式产品落地归入 P1。

### Explore

找山、筛选、进入山峰详情。
这是"下一座山去哪"的主入口。

**v0.3 升级**：Explore 同时承担三条路径的统一入口：

* 选山记录：山峰列表卡片流
* 轨迹导入：GPX/FIT 文件上传入口
* 截图识别：截图上传入口

三条入口在页面中具有同等视觉权重，不分主次。

### Mountain Detail

围绕一座山的决策页。
负责帮助用户判断这座山值不值得去、能不能去、该怎么理解路线与条件。

### Record / Activity

开始记录、照片补签、轨迹导入、截图识别、活动详情、结果沉淀、素材生成。
这是核心资产层。

### Community

基于真实活动生成的公开内容流。
这是表达层，不是产品中心。

### Profile

用户身份、头像、执照、我的记录、我的分享、省份归属。
它既承担身份表达，也承担长期回看。

### Province Heat

轻量月榜与省域贡献模块，可挂在 Profile 或相对独立的入口中。
它服务于归属感，不服务于复杂竞技。

### FAQ / 使用说明

面向上线后的用户教育、预期管理和常见问题说明。
这是正式产品的一部分，不是临时补丁页。

### Admin / QA / 内部工具

后台治理、审核、物料维护、精选内容运营、山峰数据维护、点位编辑、回归验收工具。
这些不属于普通用户主流程，但属于当前项目有效范围。

## 5. 关键用户流程

## 5.1 新用户流程

进入产品后，先完成轻 onboarding。
然后选择所属省份，建立省域身份锚点。
接着进入 Explore，看到三条路径入口。
新用户可以浏览山峰列表，点进一座山的详情页，也可以直接导入已有记录。
记录完成后，沉淀成活动对象，再决定是否分享、是否发山友圈。

### 新用户目标

* 知道先去哪
* 理解产品不是泛社交，而是围绕真实山行
* 理解产品可以接住已有的记录，不必从零开始
* 在第一次成功记录后建立"记录 → 活动 → 分享 / 发布"的闭环心智

## 5.2 老用户流程

老用户通常有三种进入方式：

* 继续找下一座山
* 把刚完成的一次山行结果带回来（GPS 记录、轨迹文件或截图）
* 回看自己已有的山行资产

首页应逐步从"纯找山入口"演进为"意图分流入口"；Explore 仍是一号找山路径，但不再独占首页逻辑。

## 5.3 路径一：选山记录流程

用户在 Explore 中找山 → 进入 Mountain Detail 做决策 → 开始 GPS 实录 → 满足核验条件后确认登顶 → 生成活动对象 → 生成分享素材 → 可发布到山友圈。

**前置要求**：必须先确定目标山峰。

## 5.4 路径二：轨迹导入流程

用户在 Explore 中点击轨迹导入入口 → 选择 GPX/FIT 文件 → 系统解析轨迹数据（距离、时长、海拔、爬升、轨迹点序列）→ 系统根据轨迹坐标自动匹配山峰 → 用户确认或手动修改匹配结果（也可跳过不匹配）→ 用户补充照片和备注（可选）→ 生成活动对象 → 生成分享素材 → 可发布到山友圈。

**前置要求**：无需先选山。

## 5.5 路径三：截图识别流程

用户在 Explore 中点击截图识别入口 → 上传其他 App（两步路、六只脚、行者等）的记录截图 → 系统 OCR 提取文字信息（距离、时长、海拔、日期、地点等）→ 系统自动识别轨迹线颜色 → 颜色阈值分割 → 骨架化 → 坐标序列 → 贝塞尔曲线平滑 → 以品牌绿 `#7ef0b4` 重新渲染轨迹 → 系统根据地点信息尝试匹配山峰 → 用户确认和修改所有识别结果 → 合理性校验通过 → 用户补充照片和备注（可选）→ 生成活动对象 → 生成分享素材 → 可发布到山友圈。

**前置要求**：无需先选山。

**合理性校验规则**：

* 只设上限，不设下限
* 平地速度上限：12–15 km/h
* 有海拔场景：每 100m 正爬升折算 1km 等效距离
* 用总等效距离 ÷ 时长判断合理性
* 超限时提示用户复核，不强制拦截
* 不校验下限

**轨迹精度要求**：不高。目标是生成好看的分享素材，不是还原精确地理路线。允许平滑修正。

## 5.6 三条路径的统一产出

三条路径最终都产出统一结构的活动对象。活动对象附带来源标签：

* 路径一产出：来源标签为 `GPS VERIFIED`
* 路径二产出：来源标签为 `UPLOADED`
* 路径三产出：来源标签为 `UPLOADED`

来源标签在分享海报、山友圈卡片、活动详情页、我的记录列表中可见。

## 6. 模块定义

# 6.1 首页 / 意图分流

## 目标

帮助用户判断本次进入产品的真实意图，而不是默认所有用户都先去找山。

## 核心职责

* 引导去找下一座山
* 引导把这次结果带回来（包含三条路径入口）
* 引导回看已有山行

## 原则

* 不做社交流首页
* 不做复杂 dashboard
* 不堆叠过多入口
* 不抢 Explore 的找山职责
* 不让 Community 抢占首页主叙事

---

# 6.2 Explore：找山与入口分流页

## 目标

快速帮助用户决定"下一座山去哪"，同时提供轨迹导入和截图识别的同等入口。

## 页面结构

顶部搜索框。
**上二下一分流区**（v0.3 新增）：
* 上方两张并排入口卡片，视觉权重相同
* 左卡片：「导入记录」— 导入轨迹文件，分享你的登顶记录
* 右卡片：「识别截图」— 上传其他 APP 轨迹截图，分享你的登顶记录
* 过渡文字：`找山出发 · 挑一座适合你的山进行登顶打卡`
* 下方：快捷筛选 chips + 山峰列表卡片流

## 三条路径入口原则

* 三条入口在页面中具有同等视觉权重
* 轨迹导入和截图识别不降格为"活动补签"或"二级功能"
* 三条入口的视觉设计应让用户一眼理解产品能做什么
* 入口文案使用“标题 + 行为描述 + 行为结果”的格式，是用户视角，不是功能术语

## 卡片固定信息

山峰主图。
山峰名。
地点。
海拔。
预计距离 / 时长。
难度等级。
执照要求。

## 不包含

不做收藏。
不做想去。
不做过多弱相关标签。

## 标签规则

沿用现有执照 / 难度体系，不再额外造一套兴趣标签体系。

## 核心判断

Explore 很重要，但不再只是找山页面。
它是产品的主入口，承载三条同等重要的路径。

# 6.3 Mountain Detail：山峰详情页

（本章内容不变，维持 v0.2 版本）

## 目标

帮助用户判断这座山值不值得去、能不能去、该怎么理解这条路线。

## 页面结构

### A. 首屏视觉区

主图轮播。
返回、分享、更多。
主 CTA：开始记录。

### B. 核心概览区

山峰名。
地点。
海拔。
距离。
爬升。
预计时长。
难度等级。
执照要求。
适合人群等级。

### C. 山峰简介区

基础简介。
经典打卡点说明。
拍照价值点说明。
山峰的独特气质和适合人群判断。

### D. 关键点位 / 参考路线区

静态路线参考图。
简要路线说明。
关键点位说明（如景观点、补给点、折返点、风险点）。
风险提示：

> 本路线仅供参考，实际请结合现场情况、天气、专业地图、向导与自身能力综合判断。

### E. 天气区

轻量天气信息展示，不做专业预测承诺。

### F. 精选攻略 / 山友经验区

来源仅限已发布山友圈内容。
需要后台人工精选。
按时间由近到远排序。
没有内容时整个模块隐藏。

## 关键原则

* Mountain Detail 是决策页，不是信息堆砌页
* 地图只做静态参考，不做专业导航
* 天气只做轻量提示，不做专业天气承诺
* 攻略区是"帮助判断"的内容，不是普通评论区
* 无精选内容时不强行留空模块

# 6.4 Record：单次真实山行

## 目标

把一次登山行为沉淀成完整对象，而不是社区附属物。

## 产品定义

单次山行是独立于山友圈内容的第一对象。

### 活动记录包含

用户是谁。
发生时间。
目标山峰（可为空，适用于导入/截图识别未匹配场景）。
地点 / 海拔。
是否登顶。
距离 / 爬升 / 时长。
轨迹。
照片。
备注。
分享素材。
公开状态与留证状态。
**来源标签**（`GPS VERIFIED` / `UPLOADED`）。

### 活动记录与山友圈关系

活动记录可以不发山友圈。
山友圈内容必须基于活动记录生成。
删除山友圈内容，不影响活动记录本身保留。

## 记录方式

1. **GPS 实录**：通过 Peak Trekker 原生 GPS 功能实时记录。
2. **轨迹导入**：上传 GPX/FIT 文件，系统解析并生成活动。
3. **截图识别**：上传其他 App 记录截图，OCR + 轨迹提取后生成活动。
4. **照片补签**：上传照片作为登顶留证。

### 记录前置规则

**GPS 实录**：必须先确定目标山峰。未确认目标山峰不得开始正式记录。高等级山峰对低等级用户不开放。

**轨迹导入**：无需先选山。系统根据轨迹坐标自动匹配山峰，用户可确认、修改或跳过。未匹配到山峰时，仍允许生成活动和分享内容。

**截图识别**：无需先选山。系统根据 OCR 提取的地点信息尝试匹配山峰，用户可确认、修改或跳过。未匹配到山峰时，仍允许生成活动和分享内容。

**照片补签**：需要选择目标山峰。

### 有效性规则

GPS 实录：沿用当前有效记录门槛、峰顶接近判断、短记录无效、漂移过滤等机制。接入更宽不等于放弃真实性边界。

轨迹导入：系统解析轨迹文件，提取完整数据。合理性校验同截图识别。

截图识别：合理性校验只设上限（参见 5.5 节）。超限提示复核，不强制拦截。

### 来源标签

| 记录方式 | 来源标签 | 说明 |
|---|---|---|
| GPS 实录 | `GPS VERIFIED` | 品牌 logo + 分隔线 + ✓ + 英文，深绿底 + 薄荷绿边框；有完整过程数据 |
| 轨迹导入 | `UPLOADED` | 文档 icon + 英文，深灰底 + 灰色边框；数据来自外部平台 |
| 截图识别 | `UPLOADED` | 文档 icon + 英文，深灰底 + 灰色边框；用户自报 + OCR 辅助 |
| 照片补签 | `GPS VERIFIED` | 品牌 logo + 分隔线 + ✓ + 英文，深绿底 + 薄荷绿边框；经过审核确认 |

尺寸与位置：

* 大尺寸约 28px，用于分享海报底部
* 中尺寸约 24px，用于活动详情页海拔旁
* 小尺寸约 20px，用于山友圈卡片数据区右侧、我的记录列表卡片右下

### 记录分层

#### 完整山行

过程证据较完整，适合成为最完整、最可信、最适合公开传播的记录类型。

#### 登顶留证

过程不一定完整，但到达结果有明确证据。
适用于"到顶才打开""只有到顶素材""后补结果"的场景。

#### 外部导入

数据来自外部平台，通过轨迹文件或截图导入。
完整数据保留，但过程证据由外部平台提供。

#### 个人归档

更偏私人记忆留存。
可以保留记忆价值，但不一定自动获得全部公开资格。

### 分层目标

这个分层的目的不是抬高门槛，而是：

* 不把真实用户挡在门外
* 不把所有记录混成同一可信等级
* 为未来导入轨迹、补签、审核和公开资格打基础

# 6.6 分享素材系统

## 目标

把一次真实山行快速转化成可传播内容。

## 战略定位

这是核心功能，不是实验功能。
它是活动结果的表达层，不是专业图表工具或模板编辑器。

## 模板体系

基础 3 个 + 高级 9 个，共 12 个模板。每个模板都支持照片合成 / 默认背景 / 透明水印导出三种背景模式。

### 基础层（永久免费）

| ID | 名称 | 上半区 | 下半区 |
|---|---|---|---|
| `basic-classic` | 经典 | 地图底图 + 轨迹线 | 山峰名、海拔大字 + 距离 / 时长 / 爬升 / 日期横排 |
| `basic-minimal` | 简约 | 纯深色底 + 发光轨迹线 | 山峰名、海拔大字 + 距离 / 时长 / 爬升 / 日期横排 |
| `basic-data` | 数据 | 海拔数字居中超大 + 山形纹理 | 次级数据横排 |

`basic-classic` 与 `basic-minimal` 通过地图开关切换，本质是同一模板的两种状态。

### 高级层（限免 → 付费）

| ID | 名称 | 核心特征 |
|---|---|---|
| `premium-photo-composite` | 照片合成 | 照片全屏 + 轨迹叠层 + 底部数据 |
| `premium-photo-overlay` | 照片叠层 | 照片全屏 + 左侧数据纵排 + 左渐变过渡 |
| `premium-split-view` | 分栏对照 | 左数据面板 + 右照片硬分割 |
| `premium-bold-number` | 大字覆盖 | 照片 + 超大半透明海拔数字 |
| `premium-data-scatter` | 数据散布 HUD | 照片 + 数据散布四角 |
| `premium-mono-film` | 黑白影调 | 照片自动转黑白 + 底部数据条 |
| `premium-altitude-profile` | 海拔剖面 | 海拔折线图 + 数据，登山独有 |
| `premium-summit-certificate` | 山峰证书 | 平面设计勋章 + 等高线纹理 |
| `premium-vertical-story` | 竖排长卡 | 照片 + 轨迹 + 数据纵排 |

模板使用 satori（Vercel HTML-to-image）实现。每个模板是一个独立 HTML/CSS 模板组件，布局使用 flexbox，字段增减时自动适应。不再使用 SVG 手动坐标计算，旧 `/api/poster/route.ts` 的 SVG 模板不作为新模板基础。
透明水印导出是主要功能按钮，不是 toggle 开关；导出透明 PNG 时使用棋盘格预览，并支持保存到相册和系统分享。

## 分享编辑器结构

* 预览区：占屏 45-48%，完整展示当前模板
* 模板选择器：基础 / 高级 Tab 切换 + 单行横滑缩略图
* 控制行：换照片、移除、地图开关、导出透明水印按钮
* 字段选择器：内联展示
* 底部操作栏：保存 / 分享（主 CTA）/ 更多

控制行在首屏底部露出约 20px，暗示用户可下滑查看更多控制项。模板缩略图只保留山峰名、海拔和 logo 的简化视觉。

## 编辑边界

当前阶段允许的选择权最多做到三层：

* 选模板
* 选主图 / 背景
* 选展示哪些字段（内联字段选择器，不进入二级页面）

字段选择规则：

* 必选字段：海拔、总距离，不可隐藏
* 可选字段：时长、爬升、日期、地点、配速、山峰名，默认开启，可关闭
* 三条路径产出的活动都支持字段选择器
* 每个字段行包含拖拽排序手柄、字段名、当前值、编辑入口、显示 / 隐藏开关
* 未识别时，海拔和总距离必须由用户手动填写
* 字段选择器内联展示在分享编辑器中，不进入二级页面
* 用户调整字段后，预览区实时更新

当前阶段明确不做：

* 复杂拖拽排版
* 大量专业分析图表
* 模板商城式扩张
* 训练分析型图层

## 内容优先级

素材中优先显示：

* 山峰名
* 海拔
* 距离
* 时间
* 爬升
* 时长
* 日期
* 地点
* 配速
* 是否登顶
* 轨迹
* 来源标签

## 视觉原则

向 Strava 式简洁表达靠近。
优先干净、数据明确、轨迹清楚。
不做复杂地形剖面图。
不做过度装饰。
不做厚重大海报感。

## 付费与预览（v0.3 新增）

* 用户可免费生成并预览分享素材
* 基础模板 3 个，永久免费、无水印、可直接导出
* 高级模板 9 个，MVP 阶段（v0.8）全部限免，显示「限免」标签，体验与免费模板一致
* 正式版（v1.0）通过 feature flag 打开高级模板付费
* feature flag 打开后，高级模板按月度会员或单次解锁判断导出权限
* 未付费用户预览高级模板时显示锁 icon、40% 遮罩和斜置「Peak Trekker 预览版」付费水印
* 付费后或限免期间不显示付费水印
* 发布到山友圈不触发模板付费 Gate
* Peak Trekker logo + 文字作为品牌标识永久存在于所有模板底部，用户不可移除；它不是付费限制

## 7. 关键业务规则

### 7.1 山峰准入规则

高难度山峰需要对应执照等级。
未达到要求时，不允许直接进入正式 GPS 实录流程。
轨迹导入和截图识别路径不受山峰准入限制。

### 7.2 记录有效性规则

GPS 实录：有效记录必须服从当前有效性门槛、峰顶接近判断、短记录无效、漂移过滤等规则。
轨迹导入 / 截图识别：合理性校验只设上限（参见 5.5 节），不强制拦截。

### 7.3 证据规则

完整山行、登顶留证、外部导入、个人归档的资格与权益应逐步形成清晰分层。
不同分层可以对应不同公开资格、审核策略和热力贡献方式。
来源标签在所有展示场景中可见。

### 7.4 地图与天气边界

（同 v0.2，不变）

### 7.5 商业化规则（v0.3 新增）

* 记录、导入、识别功能永久免费
* 基础模板 3 个，永久免费，无水印，直接导出
* 高级模板 9 个，MVP 阶段（v0.8）限免并显示「限免」标签
* 正式版（v1.0）通过 feature flag 开启高级模板付费
* feature flag 打开后，高级模板导出需月度会员或单次解锁
* 锁定态为锁 icon + 40% 遮罩 + 斜置「Peak Trekker 预览版」付费水印
* Peak Trekker logo + 文字永久存在于所有模板底部，是品牌标识，不是付费水印
* 山友圈发布不触发模板付费 Gate

### 7.6 内容规则

山友圈内容必须与活动绑定。
精选攻略必须后台人工筛选。
无精选内容时不展示该模块。

### 7.7 分享规则

每次有效活动应尽量都能产出可传播素材。
分享入口不能过深。
分享系统提供模板、主图 / 背景、内联字段选择三个维度的有限选择权。
分享系统不演化成专业海报编辑器。

### 7.8 海拔规则

海拔在找山、记录、分享、回看四段里都属于高优先级信息。
不能被弱化成普通辅助字段。

### 7.9 UI 规则

高频操作统一 icon 化。
移动端按钮区不能错行。
弹窗、底部栏、详情操作区统一规范。
一个页面视觉层级内最多 1 个主 CTA。

### 7.10 山峰物料规则

（同 v0.2，不变）

## 10. 本文档的使用说明

这份 PRD 用于定义 Peak Trekker 的目标态方向与阶段边界。
后续所有需求讨论、Codex 指令拆分、验收标准、设计回写和技术收口，都必须优先服从以下判断：

1. 它是否服务于"我的一次真实山行"这个主语？
2. 它是在强化核心资产层，还是在制造新的分支？
3. 它是在帮助用户更真实记录、更好回看、更顺畅分享，还是在把产品带去别的赛道？
4. 它是否会与当前阶段"不做重地图导航 / 不做泛社交 / 不做复杂竞技"的边界冲突？
5. 它是否在让更多真实用户更低门槛地进入产品并产出内容？

只要这五个问题里出现明显冲突，就不进入执行。
