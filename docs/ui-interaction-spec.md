# Peak Trekker UI / 交互规范 v0.5

## 1. 文档目标

本规范用于统一 Peak Trekker 的移动端界面风格、交互结构、通用组件、页面职责和体验边界，避免出现：

* 页面样式不统一
* 弹窗、卡片、列表和详情关系混乱
* 通用工具操作仍使用纯文字导致拥挤或错行
* 山友圈与活动记录视觉结构混淆
* 分享素材过度复杂，不利于快速传播
* 新增功能与主线方向冲突，造成整体产品主语不清

本规范是 **目标态交互规范**，不等同于当前代码实现。  
它服务于后续设计、开发、Codex 执行、人工验收与回归测试。

---

# 2. 主线对齐

## 2.1 产品主语

Peak Trekker 的主语不是“山”，也不是“帖子”，而是：

> **我的一次真实山行**

这意味着 UI / 交互层必须围绕下面这条主线服务：

* 山：提供锚点、决策上下文和风险边界
* Record / Activity：核心资产层
* Share：表达层
* Community：公开层
* Profile / Province Heat：长期归属层

## 2.2 当前 UI 必须服务的六条方向

1. **找山更顺**
2. **接入更宽**
3. **记录更真**
4. **海拔被看见**
5. **分享更美**
6. **回看更有意义**

## 2.3 当前阶段不做的方向

本规范不为以下方向提供主线设计支持：

* 重地图导航交互
* 离线导航体系
* 专业天气产品体验
* 组队 / 备赛工具链
* 泛社交广场
* 重成就墙
* 复杂竞技感设计
* 专业训练分析图表
* 模板编辑器产品化

## 2.4 首页与 Explore 的关系

Explore 仍然是“找山”的核心入口。  
但首页不再等于单纯的 Explore 列表，而应逐步承担 **意图分流** 职责：

* 去找下一座山
* 把这次结果带回来
* 回看自己已有的山行资产

**v0.3 升级**：Explore 从"纯找山页"升级为"三条路径的统一入口"，同时承载选山记录、轨迹导入、截图识别三条同等重要的路径。

# 3. 参考产品与借鉴边界

## 3.1 AllTrails：作为找山 / 决策参考

主要借鉴：

### A. 探索页
* 搜索 + 筛选 + 列表卡片的结构
* 山峰卡片首图为主、核心信息紧随其后的表达方式
* 列表页先给判断信息，不塞过多无关内容

### B. 山峰详情页
* 以图片、简介、路线、天气、评价为主的决策结构
* 详情页内容分区清晰，适合用户逐段判断
* CTA 明确，信息层级清楚

### C. 活动记录详情
* 单次活动作为独立对象管理
* 记录详情优先呈现图片、路线、基础数据

## 3.2 Strava：作为记录 / 分享参考

主要借鉴：

### A. 活动对象
* 单次活动是核心对象
* 活动详情独立存在
* 活动可回看、可传播

### B. 分享素材
* 默认结果图足够简单
* 核心是轨迹 + 基础数据 + 平台标识
* 适合系统分享、截图传播、二次加工

### C. 社区表达
* 信息流围绕“活动”而不是泛发帖
* 卡片信息简洁直接
* 操作区以 icon 为主，视觉清爽


## 3.3 借鉴边界

可以借鉴：
* 结构
* 信息层级
* CTA 逻辑
* 分享传播方式

不借鉴：
* 重训练分析 UI
* 复杂地图导航中心
* 多层社交互动系统
* 复杂成就墙

# 4. 全局设计原则

## 4.1 主语优先

所有页面都必须先回答：

> 这个页面是在帮助用户完成、回看、表达“这一次真实山行”吗？

如果不是，就不应占据主流程。

## 4.2 决策优先

Explore 与 Mountain Detail 的信息结构，必须服务于“这座山值不值得去”。

## 4.3 真实性优先

活动记录、山友圈内容、分享素材都必须体现真实记录感，不做虚浮表达。  
公开内容必须尽量建立在有效记录或有效证据之上。

## 4.4 接入更宽

UI 不能只服务“全程都在 Peak Trekker 里完成记录”的用户，也要接住：

* 到山顶才打开
* 行程结束后才来整理
* 先有照片，再做留证
* 在别的设备记录完，再带回结果

## 4.5 海拔优先

海拔不是普通字段。  
在 Peak Trekker 中，它是：

* 目标感
* 临场感
* 结果证明

因此在找山、记录、分享、回看四段里都必须被优先看见。

## 4.6 简洁优先

UI 不追求复杂修饰，不做厚重大海报感，不做专业图表感。  
重点是结构清楚、数据可读、图文关系明晰。

## 4.7 移动优先

所有页面优先按手机端设计，默认基准宽度为 **375px**。

## 4.8 组件优先

所有高频操作和页面结构优先复用统一组件，不允许各页面自己发明一套。

## 4.9 情感化但不煽情

情感化应通过：

* 恰当的节点文案
* 轻量的过渡动效
* 少而精的记忆锚点

来实现。  
不要用满屏热血文案、复杂插画或强情绪色块替代真正的体验设计。

# 5. 设计 Token 规范

## 5.1 核心原则

* 所有设计 token 参考 Material Design 3 的规范结构
* 保留 Peak Trekker 的深色户外视觉语言和品牌色
* 所有 token 数值为强制规范
* 新增组件必须先查 token，token 缺失才讨论扩展
* 页面实现禁止使用 token 外的样式数值绕过规范

## 5.2 间距刻度

基于 4px 基准，统一使用以下间距：

* `space-1`: 4px
* `space-2`: 8px
* `space-3`: 12px
* `space-4`: 16px
* `space-5`: 20px
* `space-6`: 24px
* `space-8`: 32px
* `space-10`: 40px
* `space-12`: 48px
* `space-16`: 64px

常见使用：
* 页面左右边距：`space-4`
* 卡片内边距：`space-4`
* 卡片内信息块间距：`space-3`
* 模块间距：`space-6`
* 大模块间距：`space-8`
* 大图区与正文区分隔：`space-10`
* 页面顶部 / 底部安全区：`space-12`
* 超大留白仅用于 hero / 空态：`space-16`

## 5.3 字号层级

统一使用以下字号组合：

* `display-l`: 28px / 36px / 700
* `headline-m`: 22px / 28px / 600
* `title-l`: 17px / 24px / 600
* `title-m`: 15px / 20px / 500
* `body-l`: 15px / 22px / 400
* `body-m`: 14px / 20px / 400
* `label-m`: 13px / 18px / 500
* `label-s`: 11px / 14px / 500

规则：
* 页面主标题统一 `headline-m`
* 山峰名 / 活动标题 / 帖子标题统一 `title-l`
* 区块标题统一 `title-m`
* 正文统一 `body-l` 或 `body-m`
* 按钮文字统一 `label-m`
* 辅助说明、时间戳、单位统一 `label-s`

## 5.4 圆角系统

* `radius-xs`: 6px
* `radius-sm`: 8px
* `radius-md`: 12px
* `radius-lg`: 16px
* `radius-xl`: 20px

规则：
* 小标签 / 小徽章：`radius-xs`
* Icon Button：`radius-sm`
* 按钮 / 输入框：`radius-md`
* 常规卡片：`radius-lg`
* 大图卡片 / 大弹窗：`radius-xl`
* 圆形元素使用 `50%`

## 5.5 颜色 Token

保留深色户外视觉语言，统一使用 11 个语义色：

* `color-primary`: `#22c55e`
* `color-on-primary`: `#08120d`
* `color-surface`: `#121416`
* `color-surface-variant`: `#23272c`
* `color-surface-elevated`: `#282d33`
* `color-on-surface`: `#f5f7f8`
* `color-on-surface-variant`: `#8d959b`
* `color-outline`: `#2f353b`
* `color-error`: `#ef4444`
* `color-success`: `#6ee7a1`
* `color-warning`: `#f59e0b`

规则：
* 禁止在组件内使用 token 外的 hex
* 禁止引入新的颜色 token，除非产品语义发生变化
* 主 CTA、关键成功状态优先使用 `color-primary`
* 警告、错误、锁定态必须走语义色，不可自造色板

## 5.6 设计资源引用与权威源

设计资源引用必须使用仓库内路径：

* 组件 JSX：`design-system/ui_kits/mobile/[文件名].jsx`
* 模板 PNG：`design-system/templates/[文件名].png`
* 组件规范：`design-system/components/[文件名].png`
* Token：`design-system/colors_and_type.css`
* 使用指南：`design-system/DESIGN_GUIDE.md`

资源冲突时的优先级：

1. ChatGPT PNG（模板视觉 + 组件规范）
2. `design-system/colors_and_type.css`
3. `design-system/DESIGN_GUIDE.md`
4. Claude Design V4 JSX
5. Handoff 文档

JSX 像素值与 token 矛盾时，以 token 为准；JSX 文案与 PNG 规范矛盾时，以 PNG 为准。

## 5.7 按钮规格

| 属性 | Primary | Secondary | Tertiary |
|------|---------|-----------|----------|
| 高度 | 44px | 44px | 44px |
| 圆角 | `radius-md` | `radius-md` | `radius-md` |
| padding-x | `space-5` | `space-5` | `space-5` |
| 字号 | `label-m` | `label-m` | `label-m` |
| 背景 | `color-primary` | `color-surface-variant` | 透明 |
| 文字 | `color-on-primary` | `color-on-surface` | `color-on-surface-variant` |
| 描边 | 无 | 可选 1px `color-outline` | 无 |

规则：
* 一个视觉层级最多一个 Primary
* 并排按钮规格必须像素级一致
* 不允许页面级自定义按钮样式绕过组件系统

## 5.8 Icon Button 规格

* 尺寸：`44x44px`
* icon 大小：`20px`
* 圆角：`radius-sm`
* 背景：透明 / surface-variant / 半透明浮层三种受控状态

必须 icon 化的高频动作：

* 返回
* 关闭
* 分享
* 编辑
* 更多
* 举报
* 删除
* 下载

## 5.9 卡片规格

* 卡片内边距：`space-4`
* 卡片间距：`space-3`
* 圆角：`radius-lg`
* 背景：`color-surface-variant` 或 `color-surface-elevated`
* 内部区块间距：`space-3`

规则：
* 禁止“卡片套卡片”
* 卡片内部用区块间距分层，不再嵌独立二级卡片
* Hero / 封面区可单独使用大图容器，但不做多层花哨叠加

# 6. 全局视觉语言

## 6.1 风格关键词

整体风格统一为：

* 深色底
* 高对比信息层级
* 大图驱动
* 简洁数据表达
* 少装饰、强结构
* 户外感、真实感、可信感

## 6.2 应避免的视觉问题

* 过多渐变块
* 无意义描边
* 过重阴影
* 复杂浮层叠加
* 卡片样式过多变体
* 大面积空白占位图
* 装饰重于信息的 banner

## 6.3 应强调的视觉特征

* 照片真实感
* 海拔与关键数据可读性
* 操作区统一
* 轨迹与记录可信感
* 结果与记忆的纪念感
* 移动端单手可操作

# 7. 全局布局规则

## 7.1 主应用框架

* 主内容容器最大宽度：`520px`
* 页面默认单列结构
* 顶部 Header sticky
* 底部 Tab Bar fixed
* 页面底部需为 Tab Bar / 安全区预留足够空间
* 主线页面优先以单列信息流组织，而不是多栏 dashboard

## 7.2 页面四段结构

移动端页面默认采用四段结构：

### A. 顶部导航区
* 返回 / 关闭
* 页面标题或轻量信息
* 分享 / 更多等工具操作

### B. 主内容区
* 内容卡片
* 图片
* 数据区
* 说明区

### C. 关键操作区
* 主 CTA
* 次 CTA
* 快速操作入口

### D. 底部导航区
* 一级导航保持固定，不频繁变化

## 7.3 安全区域

必须考虑：
* 顶部状态栏
* 底部手势区
* 底部固定 CTA 时的安全留白
* 长图滚动时最后一屏操作可见性

# 8. 通用组件规范

## 8.1 App Header

统一结构：
* 左侧：返回 / 关闭
* 中间：页面标题或简要状态
* 右侧：分享 / 更多 / 编辑等工具操作

规则：
* 顶部工具操作一律 icon 化
* 文字标题不超过两行
* 右侧工具数量通常不超过 2 个
* 375px 下不拥挤、不换行

## 8.2 Section Header

统一结构：
* 左侧标题
* 右侧轻量动作（如“查看全部”）

规则：
* 标题用 `title-m`
* 右侧动作优先 Tertiary / 文本链接，不抢主 CTA

## 8.3 Metric Strip / Metric Pill

用于承载：
* 海拔
* 距离
* 爬升
* 时长
* 是否登顶
* 执照要求
* 难度

规则：
* 重要指标优先首屏可见
* 同级指标样式统一
* 海拔优先级高于普通辅助指标
* 不堆叠过多指标导致阅读疲劳

## 8.4 Status Badge

建议统一这些状态：
* 已登顶
* 记录中
* 待补充
* 未归属
* 已发布
* 私密
* 锁定
* 仅留证

规则：
* 使用语义色
* 同一状态命名一致
* 不出现“pending / approved / qa / mock / seed”这类开发态词汇

## 8.5 Empty State

空态应包含：
* 简洁说明
* 当前页面能做什么
* 一个明确动作

不要：
* 大段解释
* 多个并列 CTA
* 大面积无意义插画

## 8.6 Toast / Banner

Toast 用于：
* 即时成功 / 失败 / 完成反馈

Banner 用于：
* 记录状态
* 发布状态
* 环境 / 权限限制

规则：
* 不把系统错误伪装成普通操作失败
* 有明确下一步时要给动作提示
* 文案必须是用户视角

## 8.7 Modal / Bottom Sheet

规则：
* 标题清晰
* 内容不拥挤
* 底部按钮区不换行
* 关闭 icon 固定位置
* 375px 下完整可见
* 不出现超大空白区域

适用场景：
* 登录拦截
* 执照限制
* 删除确认
* 字段选择
* 模板选择
* 分享方式选择

# 9. 页面规范

# 9.1 首页 / 意图分流页规范

## 目标

首页要逐步从“纯找山入口”演进为“意图分流入口”。

## 页面结构

### A. 顶部欢迎区
* 轻问候
* 当前省份 / 当前状态
* 可进入个人页

### B. 两个主入口卡
* 去找下一座山
* 把这次结果带回来

### C. 次级入口
* 回看我的山行
* 继续上次未完成整理
* 查看省域进度

### D. 轻量推荐区（可选）
* 本省热门山
* 最近一次活动快捷入口

## 视觉规则

* 不做社交流首页
* 不做复杂 dashboard
* 不同时堆很多卡
* 首屏动作不超过 2 个主入口

## 交互规则

* 点击“去找下一座山”进入 Explore
* 点击“把这次结果带回来”进入记录 / 留证 / 导入相关路径
* 次级入口不抢主入口

---

# 9.2 Explore 页规范

## 目标

快速帮助用户决定“下一座山去哪”。

## 页面结构

### A. 搜索区
* 搜索框
* 当前省份提示
* 筛选入口

### B. 上二下一入口区
* 上方两张并排入口卡片，视觉权重相同
* 左卡片：「导入记录」— 导入轨迹文件，分享你的登顶记录
* 右卡片：「识别截图」— 上传其他 APP 轨迹截图，分享你的登顶记录
* 入口文案遵循“标题 + 行为描述 + 行为结果”
* 控制高度、间距和字重，使两张卡片在 375px 下不换行、不溢出

### C. 过渡文字
* 文案固定为：`找山出发 · 挑一座适合你的山进行登顶打卡`
* 位于两张入口卡片与筛选 chips 之间
* 用于把“带回结果”过渡到“找山出发”

### D. 快捷筛选区
* 难度
* 执照等级
* 本省热门
* 距离 / 时长
* 其他少量高价值筛选

### E. 山峰列表卡片流
每张卡片固定信息：
* 山峰主图
* 山峰名
* 地点
* 海拔
* 预计距离 / 时长
* 难度等级
* 执照要求

## 不包含

* 不做收藏
* 不做想去
* 不做过多弱相关兴趣标签
* 不承担结果带回和回看资产的全部入口职责

## 卡片视觉规则

* 主图比例统一
* 图片不拉伸变形
* 无图时有合理兜底，不出现难看空白块
* 山峰名、海拔、难度、执照信息需首屏可扫读
* 海拔信息必须可快速识别

## 交互规则

* 点击整卡进入 Mountain Detail
* 点击「导入记录」进入轨迹导入流程
* 点击「识别截图」进入截图识别流程
* 搜索与筛选可组合使用
* 游客可浏览 Explore 与 Detail，不强制登录

# 9.3 Mountain Detail 页规范

## 目标

帮助用户判断这座山值不值得去、能不能去、该怎么理解这条路线。

## 页面结构

### A. 首屏视觉区
* 主图轮播
* 返回、分享、更多
* 山峰名 / 地点
* 首屏关键指标
* 主 CTA：开始记录

### B. 核心概览区
* 海拔

# 9.6 分享素材 / 水印相机规范

## 目标

把一次真实山行快速转化成可传播内容。

## 功能定位

这是核心功能，不是实验功能。  
它是活动结果的表达层，不是海报编辑器。

## 模板体系

### A. 基础层（永久免费）

| ID | 名称 | 上半区 | 下半区 |
|---|---|---|---|
| `basic-classic` | 经典 | 轨迹线（MVP 无地图底图层） | 山峰名、海拔大字 + 距离 / 时长 / 爬升 / 日期横排 |
| `basic-data` | 数据 | 海拔数字居中超大 + 山形纹理 | 次级数据横排 |

`basic-minimal` 在 v0.4 删除：MVP 无地图底图时，它与 `basic-classic` 的视觉重复。

### B. 高级层（限免 → 付费）

| ID | 名称 | 核心特征 |
|---|---|---|
| `premium-photo-composite` | 照片合成 | 照片全屏 + 轨迹叠层 + 底部数据 |
| `premium-photo-overlay` | 照片叠层 | 照片全屏 + 左侧数据纵排 + 左渐变过渡 |
| `premium-bold-number` | 大字覆盖 | 照片 + 超大半透明海拔数字 |
| `premium-data-scatter` | 数据散布 HUD | 照片 + 数据散布四角 |
| `premium-mono-film` | 黑白影调 | 照片自动转黑白 + 底部数据条 |
| `premium-altitude-profile` | 海拔剖面 | 海拔折线图 + 数据，登山独有 |
| `premium-summit-certificate` | 山峰证书 | 平面设计勋章 + 等高线纹理 |
| `premium-vertical-story` | 竖排长卡 | 照片 + 轨迹 + 数据纵排（路线层 FU-5 后补） |

`premium-split-view` 在 v0.4 删除：用户上传图片后，它与 `premium-photo-composite` 的主视觉重复。

### C. 模板生成与背景模式
* MVP 阶段在已有 SVG 模板系统上做调试 + 减法
* Satori（HTML-to-image）重写作为 V1.1+ 长期演进方向，本期不做
* `regression-debt.md` 中的 SVG 模板冻结项保留，等 V1.1+ Satori 迁移时一并解冻
* 所有 10 个模板（含 `premium-summit-certificate`）都支持照片合成 / 默认背景 / 透明水印导出三种背景模式，MVP 阶段不允许“某些模板不支持图片”的特例
* 透明水印导出是主要功能按钮，不是 toggle 开关，导出透明 PNG 时使用棋盘格预览，并支持保存到相册和系统分享
* 透明水印导出生成的水印形态跟随当前选中模板，不固定为 `basic-classic` 样式；服务端 PNG 端到端真实轨迹验证列入 FU-9 验收

## 分享编辑器结构

* 预览区：占屏 45-48%，完整展示当前模板
* 模板选择器：单行横滑缩略图（10 个模板平铺，高级模板右上角带「限免」/「付费」角标区分基础和高级，不再使用 Tab 切换）
* 控制行：换照片、移除、导出透明水印按钮。地图开关 MVP 阶段隐藏，V1.1+ MapLibre 真接入后再启用
* 字段选择器：内联展示
* 顶部右上「预览」按钮 MVP 阶段不出现，编辑器本身已是实时预览
* 底部操作栏：保存（次 CTA）/ 分享（主 CTA），平分宽度。「更多 ...」按钮 MVP 阶段不出现
* 控制行在首屏底部露出约 20px，暗示用户可下滑查看更多控制项
* 模板缩略图简化显示，只保留山峰名、海拔和 logo

## 字段选择规则

当前阶段允许的选择权最多做到三层：

* 选模板
* 选主图 / 背景
* 选展示哪些字段（内联字段选择器，不进入二级页面）

字段选择器规则：
* 必选字段：海拔、总距离，不可隐藏
* 可选字段：时长、爬升、日期、地点、配速、山峰名，默认开启，可关闭
* 三条路径产出的活动都支持字段选择器
* 每个字段行包含拖拽排序手柄、字段名、当前值、编辑入口、显示 / 隐藏开关
* 未识别时，海拔和总距离必须由用户手动填写
* 用户调整字段后，预览区实时更新

不做：
* 复杂拖拽排版
* 大量专业图表
* 模板商城式扩张
* 训练分析型图层

## 视觉原则

* 向 Strava 式简洁表达靠近
* 优先干净、数据明确、轨迹清楚
* 不做复杂地形剖面图
* 不做厚重大海报感
* 海拔默认属于高优先展示字段

## 分享链路

* 系统分享优先
* 系统分享不可用时提供降级路径
* 下载入口明确
* 可快速进入山友圈发布
* 不要让用户在“分享”和“发布”之间绕远路

# 10. 交互规范

## 10.1 页面跳转关系

原则：

* 首页 → Explore / 结果带回 / 我的记录
* Explore → Mountain Detail → Record
* Activity Detail 与 Community Detail 分离
* 分享与发布入口要靠近活动详情，不要绕远路
* FAQ 可从 Profile、登录/拦截场景、空态场景进入

## 10.2 CTA 规则

一个页面最多一个主 CTA。  
不要同时出现多个同级大按钮争抢注意力。

例如 Mountain Detail 页：
* 主 CTA：开始记录
* 次 CTA：查看路线 / 风险说明 / 查看精选经验

例如 Activity Detail 页：
* 主 CTA：分享这次山行
* 次 CTA：发布到山友圈 / 继续补充记录

## 10.3 列表与详情关系

* 列表页负责“初步筛选与判断”
* 详情页负责“完整决策与理解”
* 不要把详情页关键内容塞回列表页
* 不要把活动详情页做成社区详情页

## 10.4 隐藏规则

以下模块在无数据时直接隐藏，不做尴尬空态：

* Mountain Detail 的精选攻略
* Mountain Detail 的山友经验区
* 多余的图集区
* 无可用数据的天气区
* 无可用点位区
* 无可用扩展区块

但这些场景必须保留必要兜底：

* 活动封面
* 用户头像
* 分享素材默认图
* 山峰默认图
* FAQ 入口或说明

## 10.5 登录与权限规则

* 游客可浏览首页 / Explore / Detail
* 进入记录、发布、互动等受保护链路时需登录
* 登录后必须保留回跳
* 权限拦截文案要像引导，不要像报错

## 10.6 难度提醒 / Advisory 规则

* 山峰难度高于用户当前执照阶段时，不做硬性锁定，改为 advisory 提醒。
* 小落差（相差 1 级）使用 inline tip：amber-soft 语义色、短文案、不中断主流程。
* 大落差（相差 2 级及以上）使用 warning banner：说明建议等级、当前等级与准备建议，并提供“我了解 · 继续”主操作 + “看我的等级”次操作。
* “继续”始终是主操作；任何 advisory 都不得阻止用户进入记录、查看路线或继续浏览。

## 10.7 删除 / 举报 / 风险确认

* 一律使用确认弹窗
* 危险动作按钮位置固定
* 取消与确认层级明确
* 语气直接、不吓人、不技术化

## 11.1 基本原则

文案必须是 **用户视角**，不是系统视角，更不是开发视角。

## 11.2 明确禁止的词汇进入正式 UI

禁止直接出现在用户正式界面中的词：

* debug
* qa
* mock
* seed
* fallback
* schema
* pipeline
* env
* force
* helper
* local only
* not implemented
* todo

## 11.3 语言风格

整体语言应：

* 简洁
* 克制
* 稍带户外气质
* 稍带陪伴感
* 不说教
* 不中二
* 不热血过头

## 11.4 关键节点的语气要求

### 锁定目标山峰
偏出发仪式感，而不是“配置完成”。

### 开始记录
偏确认与陪伴感，而不是“已启动模块”。

### 接近峰顶 / 确认登顶
偏高光时刻，而不是冷冰冰状态切换。GPS 到达峰顶核验范围即视为登顶，手动确认保留仪式感，照片不是必要条件。

### 待补充 / 未归属
偏安抚与说明，而不是让用户感觉“这趟白走了”。

### 活动回看
偏纪念感，而不是纯数据复盘。

### 发布前
偏帮助表达，而不是要求用户“填写字段”。

# 12. 微动效规范

> 本章是 Peak Trekker 动效的**单一权威（canonical）**。任何动效新增 / 修改 / 收编都必须回写本章。
> 动效定调：**C+ 质感分层（L0–L3）**——动效是「完成 / 确认 / 记忆」的表达；质感来自 craft（节奏 / 编排 / 留白 / 顺滑），不是 gimmick（撒花 / 装饰转环 / 铺光）。成功与鼓励场景可有仪式感；工具属性强的场景保持克制、快速、稳定。
> 关联：[§4.9 情感化但不煽情] 的「轻量过渡动效 + 少而精记忆锚点」由本章落地；token 实现落 `design-system/colors_and_type.css` + `src/app/globals.css`（对齐 §5.1 / §5.6）。

## 12.0 制定依据与 skill 溯源

* 实际读取的 skill 文件：`gsap-core/SKILL.md`（easing L116–161、`gsap.matchMedia()` L206–238）、`gsap-performance/SKILL.md`（transform/opacity 全文）、`gsap-timeline/SKILL.md`（position/labels/defaults）、`gsap-react/SKILL.md`（useGSAP/scope/contextSafe/SSR）、`gsap-plugins/SKILL.md`（CustomEase L339）。
* 从 skill 采纳的硬规则：只动 transform/opacity（§12.5）；多步用 timeline 不用手写 delay（§12.4）；reduced-motion 用 `gsap.matchMedia()`（§12.6）；CustomEase「built-in 不够才用」(`gsap-plugins/SKILL.md:339`)，故列为按需非默认（§12.3）。
* Peak Trekker 产品判断（非 skill）：L0–L3 分层、各档时长、场景归级、收编取舍。
* **已确认（用户签字）**：§12.2 把「成功态」L3 上限从旧版 360ms 上调到 1200ms（见该节注）。

## 12.1 原则

动效用于：

* 强化状态确认
* 帮助空间切换
* 提升关键节点的完成感 / 记忆感

不用于：

* 炫技
* 装饰性循环（无状态含义的常驻 float / spin / glow）
* 强干扰注意力 / 阻塞操作

**该不该用、用多重，按 5 维判断**：① 是否标记一次阶段性成功？（是→可仪式）② 是否影响操作效率？（高→压缩或去除）③ 是否高频重复看到？（是→必须克制）④ 是否在解释状态？（否→纯装饰，砍或降级）⑤ 性能余量够不够？（不够→降级）

## 12.2 质感分层 L0–L3

| 级别 | 场景 | 时长 | 实现 | 约束 |
|---|---|---|---|---|
| **L3 仪式** | 登顶确认 / 上传成功 / 识别成功 / 归档 / 分享生成 / 记忆锚点 | 600–1200ms | 多步编排（CSS 序列或 GSAP timeline） | 可跳过、不阻塞、**一次性**（非常驻 loop） |
| **L2 状态** | 识别中 / 保存中 / 生成中 / 卡片展开 / 面板进出 / 页面切换 | 200–500ms | CSS transition / 短 keyframe | 短、清楚、低干扰 |
| **L1 工具** | 拖拽 / 编辑 / 选择 / 输入 / 地图控件 / 点击反馈 | 120–220ms | CSS transition，仅 transform/opacity | 不做仪式 |
| **L0 后台/高频** | admin / 数据表 / 长列表高频项 | ≤120ms 或无 | 仅 hover/press/loading | 默认无动效 |

> **对旧 §12.2 的修订（已确认）**：旧版把「成功态轻庆祝」封顶 240–360ms。C+ 拍板后，**真正的阶段性成功（L3 仪式）放宽到 600–1200ms**（如登顶仪式，audit 判定其编排是好 craft）；其余短档（点击/展开/面板）维持原值。这是一次有意的口径升级，不是放任所有动效变长。

## 12.3 Motion Token

**时长**（实现为 CSS 自定义属性，落 `design-system/colors_and_type.css`）：

* `motion-press`: 120ms —— 点击 / 按压反馈（L1）
* `motion-fast`: 180ms —— 微交互 / 选择（L1）
* `motion-base`: 240ms —— 展开 / 收起 / 状态切换（L2）
* `motion-enter`: 320ms —— 面板 / 卡片进出（L2，承接旧版 220–320ms 上限）
* `motion-status`: 500ms —— 较重状态过渡上限（L2）
* `motion-ceremony`: 720ms —— L3 仪式基准
* `motion-ceremony-max`: 1200ms —— L3 仪式上限
* `motion-ambient`: 1600ms —— 唯一允许的 ambient 呼吸节拍（克制，见 §12.5）

**缓动**（CSS `cubic-bezier`；GSAP 引入后用对应内置 ease，见 §12.4）：

* `ease-standard`: `cubic-bezier(.4,0,.2,1)` —— 通用进出
* `ease-out`: `cubic-bezier(.16,1,.3,1)` —— 进入 / 展开（减速收尾）
* `ease-emphasis`: `cubic-bezier(.34,1.4,.5,1)` —— L3 克制过冲（**不是** 1.7 的弹跳）
* `ease-pulse`: `ease-in-out` —— ambient 呼吸

规则：页面实现禁止用 token 外的时长 / 缓动数值绕过本规范（对齐 §5.1）；默认用 token，缺档才讨论扩展。

## 12.4 CSS / GSAP 分工

* **默认 CSS**：单步 transition / hover / press / fade / slide / 单 keyframe 状态脉冲（L0–L2，以及能用纯 CSS 序列表达的 L3）。
* **GSAP 仅在**多步仪式**确需 timeline 编排**时引入（position/labels/嵌套、可跳过控制、统一 matchMedia）。引入时机已定：**推迟到 FU-87 第一个真需要 timeline 的新仪式作 pilot**；FU-76 全程 CSS（含登顶删装饰 loop 也用 CSS）。
* GSAP 缓动对应：`ease-standard→power2.inOut`、`ease-out→power3.out`、`ease-pulse→sine.inOut`；`ease-emphasis` 内置 ease 不足时才用 `CustomEase.create("pt-emphasis",".34,1.4,.5,1")`（依据 `gsap-plugins/SKILL.md:339`「built-in 不够才用」）。
* React 集成（GSAP 引入后）：用 `useGSAP({scope})` 自动清理；可跳过仪式用 `contextSafe` 包 `tl.progress(1)`；不在 SSR 执行 GSAP。

## 12.5 性能红线

* **只动 `transform`（x/y/scale/rotation）和 `opacity`**；禁止动画 `width/height/top/left/margin/padding`（触发 layout，掉帧）。现有违例（扫描线 `top`、进度条 `width`、slider `left`）在 §12.12 收编 retune。
* `will-change: transform` 仅加在确实在动的元素上，动完移除。
* **常驻 loop 默认禁止**；唯一例外是 `motion-ambient` 单点呼吸，且必须解释状态（如"识别进行中"），不得纯装饰。

## 12.6 无障碍（reduced-motion）

* 必须尊重 `prefers-reduced-motion: reduce`。
* **CSS 阶段（FU-76）**：全局 `@media (prefers-reduced-motion: reduce)` 统一降级（仪式→直接终态、loop→停、过渡→近 0ms）。
* **GSAP 阶段（FU-87+）**：用 `gsap.matchMedia()` 的 `reduceMotion` 条件（`duration:0` / 跳过），随媒体查询自动 revert；CSS 全局兜底保留。架构在 Phase B0 即预留接缝，不返工。
* reduced-motion 不是「关掉一切」，而是「去掉位移 / 缩放 / 闪烁，保留必要的状态可见性」。

## 12.7 每个动效点的方案格式（6 字段）

任何动效点方案（V1）必须逐点写明：① **触发时机** ② **目的**（对应 §12.1 五维）③ **级别**（L0–L3）④ **实现**（CSS 还是 GSAP / 用哪个 token）⑤ **reduced-motion 降级**（明确行为）⑥ **移动端验收证据**（375px 真机或视频，截图不算）。

> 每份动效方案文档顶部还须带「skill 使用头部」：实际读取的 skill 文件路径(+行号) / 采纳规则 / 产品判断 / 待用户拍板项（防「先出方案再补 skill 背书」）。

## 12.8 建议使用场景

* 首页意图卡点击（L1 / L2）
* 开始记录成功（L2 / L3）
* 接近峰顶提示（L2）

## 12.9 禁止 / 慎用

* 每个字段旁有编辑入口，用户可修改
* 未识别出的字段显示为空，用户可手动填写
* 合理性校验：超限时在对应字段旁显示提示，不阻塞流程

* 确认后生成活动对象
* 来源标签自动标记为 `UPLOADED`

* 合理性校验提示为警告态，不阻塞确认按钮
* 整个流程在移动端 375px 下可正常完成
* 不使用技术术语（不说"OCR""分割""骨架化"）

## 16.4 视觉规则

* 截图预览区不能过小，用户需要能看清原始记录
* 轨迹颜色自动识别过程应有明确处理状态
* 重绘轨迹预览应展示 Peak Trekker 风格，让用户看到最终效果

# 17. 分享模板权限 Gate 交互规范（v0.3 新增）

## 17.1 适用场景

用户在分享素材生成后，点击"导出高清"或"下载"时触发。
当 feature flag 关闭时，此章节所有规范不生效。

## 17.2 预览态

* 用户可免费生成和预览分享素材
* 2 个基础模板预览和导出始终无水印
* MVP 阶段（v0.8）8 个高级模板显示「限免」标签，体验与免费模板一致
* 正式版（v1.0）通过 feature flag 打开高级模板付费
* feature flag 打开后，高级模板未解锁时显示锁 icon、40% 遮罩和斜置「Peak Trekker 预览版」付费水印
* 付费后或限免期间不显示付费水印
* Peak Trekker logo + 文字作为品牌标识永久存在于所有模板底部，用户不可移除

## 17.3 导出态

* 用户点击导出/下载时，通过 `checkTemplateAccess()` 检查模板权限
* 基础模板（2 个）：直接导出高清无水印版本
* 高级模板（8 个）已解锁：直接导出高清无水印版本
* 高级模板（8 个）未解锁：显示付费引导，或保留带水印预览

## 17.4 付费引导

* 弹窗或 Bottom Sheet
* 说明当前高级模板需要解锁
* 展示购买选项（月度会员 / 单次解锁）
* 引导文案是用户视角：
  * "这个高级模板需要解锁"
  * "保留基础模板免费导出，也可以解锁更多表达方式"
* 不使用恐吓或施压语气
* 关闭后仍可继续预览（带水印）

## 17.5 模板权限提示

* Profile 或设置中可显示当前订阅层级 / 高级模板试用到期时间
* 高级模板即将过期时不做弹窗打扰，只在导出时自然触发
* 基础模板不展示付费提示

## 17.6 视觉规则

* 付费水印位于画面中部斜置，不遮挡关键数据区域
* 锁定态遮罩透明度约 40%，仍能判断模板效果
* 付费引导 UI 保持克制，不做全屏拦截
* 375px 下付费弹窗完整可见、按钮不换行

# 18. 来源标签展示规范（v0.3 新增）

## 18.1 标签类型

| 标签 | 样式建议 | 颜色 |
|---|---|---|
| `GPS VERIFIED` | 品牌 logo + 分隔线 + ✓ + 英文 | 深绿底 + 薄荷绿边框 |
| `UPLOADED` | 文档 icon + 英文 | 深灰底 + 灰色边框 |

## 18.2 展示位置

* 分享海报：底部，大尺寸约 28px
* 山友圈 Feed 卡片：活动数据区右侧，小尺寸约 20px
* 活动详情页：海拔旁，中尺寸约 24px
* 我的记录列表：活动卡片右下，小尺寸约 20px

## 18.3 视觉规则

* 标签文案必须使用英文 `GPS VERIFIED` / `UPLOADED`
* 标签使用 `label-s` 字号
* 标签使用 `radius-xs` 圆角
* 标签不抢占主视觉层级
* `GPS VERIFIED` 标签稍带信任感色彩
* `UPLOADED` 标签为中性色，不带贬义

# 19. 本规范的使用说明

后续任何 UI / 交互调整，都必须优先回答这 5 个问题：

1. 它是否服务于“我的一次真实山行”这个主语？
2. 它是在强化核心资产层，还是在制造新的分支？
3. 它是否让用户更容易找山、记录、回看、分享？
4. 它是否会把产品误导向重导航、泛社交、复杂竞技或专业图表工具？
5. 它是否在 375px 下仍然成立？

如果答案存在明显冲突，则不进入设计和开发执行。
